# Wazuh Server — Full Stack (Manager + Indexer + Dashboard)

> ℹ️ **For the one-command single-host Docker PoC, start at the [root README](../README.md).**
> The Wazuh stack there is already wired into the root `docker-compose.yml` and its TLS
> certs are generated by `up.sh`. Hard-coded example IPs (`192.0.2.x`) below are
> historical examples; in the Docker stack components resolve by name
> (`wazuh.manager`, `wazuh.indexer`, `vpn.local`).

Security posture manager for the eduVPN mTLS integration, powered by [Wazuh](https://wazuh.com/) 4.14.3.

The Wazuh Manager tracks agent status on client devices. The eduVPN server queries the Wazuh API to determine whether a connecting device has an active, compliant agent before authorising VPN access.

## 1. Role in the Architecture

The Wazuh stack serves as the **device posture authority** for the system. It:

- Runs the **Wazuh Manager**, which accepts agent connections from client devices and tracks their status (Active / Inactive / Disconnected).
- Exposes the **Wazuh API** (port 55000) so the eduVPN server can query agent status by Device ID.
- Provides the **Wazuh Dashboard** (port 443) for administrators to inspect agents, alerts, and security events.
- Stores and indexes security events via the **Wazuh Indexer** (OpenSearch).

**How it connects to the CA**: There is no direct certificate-chain dependency. The CA issues client certificates containing a Device ID. The eduVPN server extracts that Device ID and looks up the corresponding agent in Wazuh via the API. The linkage is logical (Device ID mapping), not cryptographic. Optionally, the CA can issue a TLS certificate for the Wazuh API (see CA server README §6.4).

## 2. Prepare a Debian 13 Server

Start from a fresh Debian 13 (Trixie) minimal install. Run all commands as `root` or with `sudo`.

### 2.1 System updates

```bash
apt update && apt upgrade -y
```

### 2.2 Install Docker CE

Use Docker's official convenience script ([docs.docker.com](https://docs.docker.com/engine/install/debian/#install-using-the-convenience-script)):

```bash
curl -fsSL https://get.docker.com -o get-docker.sh
sh get-docker.sh

# Verify
docker run --rm hello-world
```

### 2.3 (Optional) Allow a non-root user to run Docker

```bash
usermod -aG docker <your-username>
# Log out and back in for the group change to take effect
```

### 2.4 Kernel tuning (required for Wazuh Indexer)

The Wazuh Indexer (OpenSearch) creates many memory-mapped areas. The Linux default limit is too low:

```bash
# Set immediately
sysctl -w vm.max_map_count=262144

# Persist across reboots
echo "vm.max_map_count=262144" >> /etc/sysctl.conf
```

## 3. Deploy the Wazuh Stack

### 3.1 Copy files to the server

> **Note:** this directory used to ship a standalone `docker-compose.yml` and
> `.env.example`. They were removed before publication because they published the
> Wazuh agent-enrolment and API ports (1514/1515/55000) straight to the host,
> silently undoing the hardening the root stack applies — see
> [`VENDORED.md`](VENDORED.md) and the root README's limitations. Model a
> standalone deployment on the `wazuh.*` services in the root
> [`docker-compose.yml`](../docker-compose.yml), or use upstream
> [wazuh-docker](https://github.com/wazuh/wazuh-docker) directly.

Copy the following from this repository's `wazuh-server/` directory to the server:

```
wazuh-server/
├── generate-certs.yml
└── config/
    ├── certs.yml
    ├── wazuh_cluster/
    │   └── wazuh_manager.conf
    ├── wazuh_indexer/
    │   ├── wazuh.indexer.yml
    │   └── internal_users.yml
    └── wazuh_dashboard/
        ├── opensearch_dashboards.yml
        └── wazuh.yml
```

### 3.2 Create the `.env` file

Create a `.env` next to your compose file. In the supported single-host stack these
values live in the repository-root [`.env`](../.env) — use the **same names** so the
two stay consistent:

**Change ALL default passwords** before starting. At minimum, update:
- `WAZUH_INDEXER_PASS` — used by Manager and Dashboard to connect to the Indexer
- `WAZUH_API_PASS` — used by the Dashboard and by the eduVPN posture check to query the Manager API

### 3.3 Update password hashes (if you changed INDEXER_PASSWORD)

If you changed `INDEXER_PASSWORD` from the default, you must also update the bcrypt hash in `config/wazuh_indexer/internal_users.yml` for the `admin` user.

Generate a new bcrypt hash:

```bash
# Using Docker (no extra tools needed)
docker run --rm -it wazuh/wazuh-indexer:4.14.3 \
  bash -c "cd /usr/share/wazuh-indexer/plugins/opensearch-security/tools && \
  bash hash.sh -p '<YOUR_NEW_PASSWORD>'"
```

Replace the `hash:` value for the `admin` user in `internal_users.yml` with the output.

### 3.4 Generate internal TLS certificates

This step generates the TLS certificates used for communication between the three Wazuh components (Manager ↔ Indexer ↔ Dashboard). Run this **once** before the first start:

```bash
docker compose -f generate-certs.yml run --rm generator
```

This populates `config/wazuh_indexer_ssl_certs/` with the generated certificates and keys.

### 3.5 Start the stack

```bash
docker compose up -d
```

Check the logs to confirm initialisation:

```bash
docker compose logs -f
```

> **Note:** Expect `Failed to connect to Wazuh indexer port 9200` messages for the first ~60 seconds. This is normal — the Indexer takes about a minute to initialise.

### 3.6 Access the Dashboard

Open `https://<SERVER_IP>:443` in your browser.

- **Username:** `admin`
- **Password:** the value of `INDEXER_PASSWORD` from your `.env`

> The Dashboard uses a self-signed certificate, so your browser will show a security warning. This is expected.

## 4. Post-Deployment Configuration

### 4.1 Verify all containers are running

```bash
docker compose ps
```

All three services (`wazuh.manager`, `wazuh.indexer`, `wazuh.dashboard`) should show `Up`.

### 4.2 Test the API

From the server itself:

```bash
curl -k -u wazuh-wui:'MyS3cr37P450r.*-' \
  https://localhost:55000/security/user/authenticate
```

A successful response returns a JWT token in JSON format.

### 4.3 Change the API password (optional, already handled via .env)

The API password is set via the `API_PASSWORD` environment variable in `.env`. If you need to change it after initial deployment:

```bash
docker compose down
# Edit .env with the new API_PASSWORD
# Also update config/wazuh_dashboard/wazuh.yml with the new password
docker compose up -d
```

### 4.4 Replace the Dashboard TLS certificate with a step-ca certificate

By default the Dashboard uses a self-signed certificate. To replace it with one signed by your CA:

**Step 1 — Install the `step` CLI on the Wazuh server** (same as client README section 5.1):

```bash
curl -fsSL "https://github.com/smallstep/cli/releases/download/v0.29.0/step-cli_0.29.0-1_amd64.deb" -o /tmp/step-cli.deb
dpkg -i /tmp/step-cli.deb
rm /tmp/step-cli.deb
```

**Step 2 — Bootstrap against the CA:**

```bash
step ca bootstrap \
  --ca-url https://192.0.2.20:9000 \
  --fingerprint <ROOT_CA_FINGERPRINT> \
  --install
```

**Step 3 — Request a certificate for the Wazuh server:**

```bash
step ca certificate "wazuh.dashboard" \
  /etc/ssl/certs/wazuh-dashboard.crt \
  /etc/ssl/private/wazuh-dashboard.key \
  --san wazuh.dashboard \
  --provisioner admin
```
(Use the `admin` provisioner — `device-certs` is reserved for `device-<machine-id>`
client identities. Enter the CA/admin provisioner password when prompted.)

**Step 4 — Copy the certificate into the location the Dashboard container mounts from:**

```bash
cp /etc/ssl/certs/wazuh-dashboard.crt /root/wazuh-server/config/wazuh_indexer_ssl_certs/wazuh.dashboard.pem
cp /etc/ssl/private/wazuh-dashboard.key /root/wazuh-server/config/wazuh_indexer_ssl_certs/wazuh.dashboard-key.pem
```

**Step 5 — Restart the stack:**

```bash
docker compose down && docker compose up -d
```

**Step 6 — Set up automatic renewal:**

```bash
cat << 'CRON' > /etc/cron.d/step-ca-wazuh-renew
# Renew Wazuh Dashboard certificate every 12 hours
0 */12 * * * root step ca renew /etc/ssl/certs/wazuh-dashboard.crt /etc/ssl/private/wazuh-dashboard.key --force --exec "cp /etc/ssl/certs/wazuh-dashboard.crt /root/wazuh-server/config/wazuh_indexer_ssl_certs/wazuh.dashboard.pem && cp /etc/ssl/private/wazuh-dashboard.key /root/wazuh-server/config/wazuh_indexer_ssl_certs/wazuh.dashboard-key.pem && docker compose -f /root/wazuh-server/docker-compose.yml restart wazuh.dashboard" >> /var/log/step-wazuh-renew.log 2>&1
CRON

chmod 644 /etc/cron.d/step-ca-wazuh-renew
```

## 5. Firewall Considerations

In the Docker Compose stack the Wazuh services talk to each other over the internal
`eduvpn-net` bridge and are **not** published to the host, except the Dashboard UI
(`8443:5601`). The manager's agent/enrollment/API ports (1514/1515/55000) are
`expose`-only — reachable from other containers on the bridge but not from the host —
so no host firewall rule is needed to keep them internal. On a bare-metal manager
instead, restrict 1514/1515/55000 to the agent/consumer networks, and remember that
Docker's published ports bypass `ufw`/`nftables` (see the CA README's firewall note).

## 6. Connecting from the eduVPN Server

The eduVPN server's posture check reaches the manager API as
`https://wazuh.manager:55000` over the `eduvpn-net` bridge, configured in the portal's
`PostureCheck` block (see [`eduvpn-integration/`](../eduvpn-integration/README.md)). It
authenticates with `WAZUH_API_USER`/`WAZUH_API_PASS` from the central `.env`, obtains a
JWT, and queries `/agents?name=device-<machine-id>` for the agent's status. No host
networking is involved — the server resolves `wazuh.manager` by its Docker network alias.

## 7. Reference

### Ports

| Port | Protocol | Purpose | Who connects |
|---|---|---|---|
| 443 | HTTPS | Wazuh Dashboard (web UI) | Admin browsers |
| 55000 | HTTPS | Wazuh Manager API | eduVPN server |
| 1514 | TCP | Agent ↔ Manager communication | Wazuh agents on clients |
| 1515 | TCP | Agent enrollment (first connection) | Wazuh agents on clients |
| 514 | UDP | Syslog collection | (optional) |

### Volumes

| Volume | Purpose |
|---|---|
| `wazuh_etc` | Manager configuration and keys |
| `wazuh_logs` | Manager logs |
| `wazuh_queue` | Event queue |
| `wazuh-indexer-data` | Indexed log data (OpenSearch) |
| `wazuh-dashboard-config` | Dashboard plugin configuration |
| (+ 9 more) | API config, integrations, filebeat, etc. |

### Environment Variables

| Variable | Default | Purpose |
|---|---|---|
| `WAZUH_VERSION` | `4.14.3` | Docker image tag for all three components |
| `INDEXER_PASSWORD` | `SecretPassword` | Indexer admin password |
| `API_USERNAME` | `wazuh-wui` | Manager API username |
| `API_PASSWORD` | `MyS3cr37P450r.*-` | Manager API password |
| `DASHBOARD_PASSWORD` | `kibanaserver` | Dashboard internal user password |
| `INDEXER_JAVA_MEMORY` | `1g` | Java heap for the Indexer (OpenSearch) |
| `DASHBOARD_PORT` | `443` | Host port for the Dashboard |
| `API_PORT` | `55000` | Host port for the API |
| `AGENT_CONNECTION_PORT` | `1514` | Host port for agent communication |
| `AGENT_ENROLLMENT_PORT` | `1515` | Host port for agent enrollment |

### Useful commands

```bash
# Check all container status
docker compose ps

# View logs (all services)
docker compose logs -f

# View logs (manager only)
docker compose logs -f wazuh.manager

# Restart the stack
docker compose restart

# Stop the stack
docker compose down

# Stop and remove all data (DESTRUCTIVE)
docker compose down -v

# Get API token via curl
curl -k -u wazuh-wui:'<password>' \
  https://localhost:55000/security/user/authenticate

# List agents via API
TOKEN=$(curl -sk -u wazuh-wui:'<password>' \
  https://localhost:55000/security/user/authenticate \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")
curl -sk -H "Authorization: Bearer $TOKEN" \
  https://localhost:55000/agents?select=id,name,status
```
